# 🛡️ PROJECT ARCHITECTURE SPECIFICATION: INSIDER-SHIELD SOC

## 1. Project Overview
Insider-Shield is an Enterprise-Grade, Open-Source Insider Threat Detection and Data Loss Prevention (DLP) Platform. It combines a zero-touch Chrome Enterprise Extension (Endpoint Agent) with a modular Next.js SOC Command Center (Dashboard) to deliver real-time asset tracking, dynamic remote policy enforcement, and identity-linked threat monitoring.

## 2. Technology Stack & Frameworks
- Frontend Dashboard: Next.js 14+ (App Router), React 18, Tailwind CSS, Lucide React, Recharts, Leaflet / React-Leaflet
- Endpoint Extension Agent: Manifest V3 (Vanilla JS / Web APIs), Chrome Enterprise Managed Storage API (`chrome.storage.managed`), WebSockets
- Backend Ingestion & Real-Time Engine: Next.js API Routes / WebSockets
- Deployment & Hosting: Vercel

## 4. Notes on Current Status

As of Phase 1, only the documentation (`PLAN.md`, `WORKLOG.md`) and the
`extension/` scaffold exist. The `src/` dashboard/backend tree described
above has not been created yet — the project currently still uses the
default `app/` directory generated by `create-next-app`. Migrating to the
`src/app/` layout and building out `users/`, `assets/`, `policies/`, and
the ingestion API are Phase 2 work; see `PLAN.md` for sequencing.

All extension files committed so far are structural placeholders. No
clipboard content, keystrokes, or page data are actually captured or
transmitted — event listeners currently only log locally for scaffolding
purposes. Any real DLP data collection must be scoped, documented, and
gated behind explicit enterprise policy configuration (`chrome.storage.managed`)
before being enabled, per the compliance considerations in `PLAN.md`.
